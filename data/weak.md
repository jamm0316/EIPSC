# 정처기 실기 약점 단원 정리 (핵심요약 발췌)

weakness DB의 미해결 약점을 시각지도 경로 순으로 묶고, 시나공 「2026 실기 핵심요약」(p.쪽)에서 해당 내용을 줄여 옮겼다. 각 항목 끝의 **확인 문항**은 키워드찾기 130(K#)과 SQL 17(S#) 번호다.

1. 지도 경로를 소리 내어 말한다 (예: 네트워크 > 4 안전 배달 > 오류검출).
2. 아래 요약을 3분 읽고 **트리거 → 답** 한 줄만 머리에 남긴다.
3. 확인 문항의 답을 가리고 쓴다. 틀리면 지도 백지에 그 칸만 빨간색으로 표시한다.

표시: 🔴 3회 이상 반복된 구조적 약점 · 🟠 아직 보강 전 · ⚪ 보강함. 핵심요약에 없는 내용은 출처를 따로 적었다.

## net 1. 네트워크 — 패킷 하나의 여정

가장 많이 비어 있는 단원이다. 계산형(서브넷)과 용어형(나머지)으로 나뉜다.

### 1 주소 붙이기 > 서브넷 🔴 · NAT (p.106, p.111)

- **IPv4** 8비트×4 = 32비트, A~E 클래스. **IPv6** 16비트×8 = 128비트, 16진수 + 콜론 구분. IPv6 주소 체계는 유니캐스트(1:1) · 멀티캐스트(1:다) · 애니캐스트(가장 가까운 1).
- **서브네팅 순서** (p.106 예제: 192.168.1.0/24를 FLSM으로 3개로 나누기)
    1. /24 → 마스크 255.255.255.0, 마지막 8비트가 호스트 영역
    2. 네트워크 3개를 표현하려면 2비트 필요(2² = 4 ≥ 3) → 마스크 끝 8비트 = 11000000 = 192
    3. 남은 6비트가 호스트 → 블록 크기 2⁶ = 64
    4. 범위: .0~63 / .64~127 / .128~191 (첫 주소 = 네트워크, 끝 주소 = 브로드캐스트, 사용 가능 호스트 = 64−2 = 62)
- **NAT**: 공인 IP 1개에 사설 IP 여러 개를 연결한다. 한 번에 1개만 외부 접속 가능한 한계는 **IP 마스커레이드**로 해결한다. Translation이지 Transfer가 아니다.
- 확인 문항: K#102 · #103 · #104 · #105(IPv6) · #116(NAT)

### 2 상대 찾기 > ARP/RARP 🟠 (p.109)

- **ARP**: IP 주소 → MAC 주소. **RARP**: MAC 주소 → IP 주소 (Reverse).
- 트리거: "IP를 물리적 주소로" → ARP, "물리적 주소를 IP로" → RARP
- 확인 문항: K#84 · #112

### 3 길 찾기 > 라우팅 프로토콜 ⚪ (p.111)

| 구분 | 프로토콜 | 알고리즘 | 트리거 |
| --- | --- | --- | --- |
| IGP (AS 내부) | RIP | 벨만-포드, 거리 벡터 | "가장 널리 사용", 소규모, 홉 수 |
| IGP (AS 내부) | OSPF | 다익스트라, 링크 상태 | "RIP 단점 해결", 대규모 |
| EGP (AS 간) | BGP | 경로 벡터 | "처음엔 전체 라우팅 테이블, 이후 변화분만" |

- RIP는 보강 후에도 재실패했다. **"홉 수 · 최대 15 · 소규모"면 RIP, 이름(Open Shortest Path First) 그대로 최단 경로면 OSPF**로 구분한다.
- 확인 문항: K#118

### 4 안전 배달 > 패킷교환 🟠 (p.108)

| 구분 | 가상 회선 | 데이터그램 |
| --- | --- | --- |
| 연결 | 논리 회선을 **미리 설정** (연결형) | 경로 설정 없음 (비연결형) |
| 경로 | 모든 패킷이 같은 경로 | 패킷마다 독립 경로 |
| 순서 | 발생 순서대로 도착 | 순서 무관, **수신 측이 재정리** |
| 주소 | 회선 번호로 충분 | 패킷마다 목적지 **완전한 주소** 필요 |

- 함정: 연결형/비연결형만 보고 TCP/UDP를 쓰면 오답이다. 패킷교환은 **교환 방식**의 이름을 묻는다. TCP는 가상 회선 기반, IP·UDP는 데이터그램 기반이다(p.108).
- 확인 문항: K#111

### 4 안전 배달 > 오류검출 🔴 · HDLC 🟠

핵심요약 실기에는 이 내용이 없다. 아래는 벼락치기 PDF §1과 필기 요약 p.98에서 옮겼다.

| 방식 | 원리 | 능력 | 트리거 |
| --- | --- | --- | --- |
| 패리티 | 1비트를 붙여 1의 개수를 짝/홀로 맞춤 | 검출만 (1비트) | "블록 끝에 1비트 검사 비트" |
| CRC | 다항식으로 나눈 나머지 비교 | 검출만 (집단 오류) | "다항식", "FCS", "HDLC", "집단 오류" |
| 해밍 코드 | 2의 거듭제곱 위치에 패리티 비트 배치 | 검출 + **정정** | "스스로 수정" |
| 체크섬 | 데이터 합산 값 비교 | 검출만 | "합산값 비교" |

- 정정 방식 이름: **FEC**(전진 오류 수정, 수신 측이 스스로 고침 = 해밍) vs **BEC**(후진 오류 수정, 재전송 요청 = ARQ).
- **HDLC**: 비트 위주의 데이터 링크 제어 프로토콜. 프레임 끝의 FCS 검사에 CRC를 쓴다.
- 확인 문항: 키워드130에 없음 → 2025-3#4 · 2025-1#3 · 2023-2#12 · 2023-2#13 재풀이

### 특수망 > 애드혹 🟠 (p.109)

- **애드 혹 네트워크**: 고정 유선망 없이 **모바일 호스트만으로** 구성한 네트워크. 재난 현장처럼 단기간 쓰거나 유선망을 깔기 어려운 곳에 맞다.
- 헷갈리는 형제: 메시 네트워크(대규모 디바이스용 특수 목적망) · 피코넷(블루투스·UWB로 만든 무선망)
- 확인 문항: K#115

### 함께 보면 좋은 것 (p.106~109)

- OSI 7계층 순서: 물리 → 데이터 링크 → 네트워크 → 전송 → 세션 → 표현 → 응용 (K#106 · #107)
- 프로토콜 3요소: 구문 · 의미 · 시간 (K#109)
- ICMP: IP와 함께 오류 처리·경로 변경 제어 메시지 (K#113)

## sec 2. 보안 — 공격자 vs 방어자

보강 전 태그가 가장 많다. 용어 이름을 쓰는 문제가 대부분이라 **트리거 단어 → 이름** 연결이 핵심이다.

### 4 공격 > 공격기법 🟠 (p.67~69)

| 공격 | 트리거 | 원리 |
| --- | --- | --- |
| SYN Flooding | "3-way handshake", "의도적으로 중단", "대기 상태" | 가짜 클라이언트가 SYN만 보내고 마지막 ACK를 안 보내 서버를 기다리게 만든다 |
| SMURFING (스머핑) | "ICMP", "브로드캐스트" | IP·ICMP 특성으로 대량 데이터를 한 곳에 몰아 보낸다. 대책: 라우터에서 브로드캐스트 차단 |
| LAND Attack | "송신 IP = 수신 IP = 대상", "자신에게 무한 응답" | 대상이 자기 자신에게 계속 응답하게 만든다 |
| Ping of Death | "패킷 크기를 허용 범위 이상" | 비정상적으로 큰 ping으로 망을 마비시킨다 |
| 세션 하이재킹 | "인증 후 세션 가로채기", "시퀀스 번호" | 인증 정보 없이 원래 클라이언트인 척한다 |
| ARP 스푸핑 | "자신의 MAC을 대상 것으로 변조" | ARP 취약점으로 패킷을 가로챈다 |
| 스니핑 | "중간에서 도청", "수동적 공격" | 남의 패킷을 엿듣는다 |
| 워터링 홀 | "자주 방문하는 사이트를 사전 감염" | 목표가 오길 기다리는 웹 기반 공격 |
| APT | "특정 조직", "활동 거점", "때를 기다리며", "지능형 지속" | 조직적으로 침투해 오래 숨어 있다 정보를 빼돌린다 |
| 사회 공학 | "사람을 속여", "비기술적" | 신뢰를 이용해 보안 절차를 깬다 |
| 타이포스쿼팅 | "주소 오타", "유사 도메인 미리 등록" | URL 하이재킹 |

- 함정: 2024-1#17은 "조직적·장기간·거점"이라 **APT**다. 사회 공학은 "사람의 심리"가 핵심이다.
- 계층으로 구분: SYN Flooding = TCP(전송), 스머핑·Ping of Death = ICMP(네트워크)
- 확인 문항: K#85(LAND) · #86 · #87 · #88 · #93 · #121

### 4 공격 > 악성코드 ⚪ (p.69~70)

| 이름 | 트리거 |
| --- | --- |
| Rootkit | 침입 사실을 **숨긴 채** 백도어·트로이목마 설치, 흔적 삭제, 관리자 권한 획득을 묶은 **프로그램 모음** |
| 키로거 | 키보드 입력을 몰래 기록해 ID·비밀번호를 빼간다 |
| 봇넷 | 감염된 다수 컴퓨터(좀비 PC)가 네트워크로 묶인 형태. C&C 서버가 조종해 DDoS에 쓴다 |
| 웜 | **네트워크로 스스로 복제**해 부하를 높인다. 숙주가 필요 없다 |
| 바이러스 | 자기 복제 + **다른 프로그램 감염**(숙주에 기생) |
| 트로이 목마 | 정상 프로그램으로 위장, **자기 복제 능력 없음** |
| 랜섬웨어 | 파일을 암호화하고 돈을 요구한다 |
| 백도어 | 설계자가 만든 비밀 통로. 탐지: 무결성 검사·열린 포트·로그 분석·SetUID 파일 검사 |

- 2024-1#15 Rootkit: "숨긴다 + 여러 도구의 모음"이면 Rootkit이다. Spyware·Worm과는 숨김 여부로 갈린다.

### 5 방어 > 보안프로토콜 🟠 (p.44, p.66~67)

| 프로토콜 | 계층·용도 | 트리거 |
| --- | --- | --- |
| IPsec | **네트워크 계층**, IP 패킷 단위 변조 방지·은닉 | 구성 AH·ESP, 모드 터널·전송, 양방향 암호화 |
| SSL | TCP/IP와 응용 계층 사이 | 인증·암호화·무결성 보장 |
| S-HTTP | 웹 메시지 전체 암호화 | 클라이언트↔서버 모든 메시지 |
| SSH | 원격 접속 | **22번 포트**, 클라이언트 공개키를 서버에 등록 |
| VPN | 공중망 위의 전용 회선처럼 | SSL VPN(PC에 클라이언트 설치) / IPSec VPN(네트워크끼리 연결) |

- VPN과 관계: VPN은 "터널"이고, 그 터널을 암호화하는 도구가 IPSec 또는 SSL이다.
- 확인 문항: K#50 · #90

### 5 방어 > 소프트웨어보안(템퍼 프루핑) 🟠

핵심요약에 없다(벼락치기 §2). **Tamper(조작) + Proofing(방지)** = 소프트웨어 변조 방지 기술이다. 비정상 수정을 감지하면 소프트웨어가 오작동하게 해 악용을 막는다. 수단은 해시 함수·핑거프린트·워터마킹·난독화다.

### 3 비밀 만들기 > 암호알고리즘 ⚪ (p.65~66)

| 알고리즘 | 종류 | 블록 / 키 | 트리거 |
| --- | --- | --- | --- |
| DES | 대칭(개인키) | 64 / 56비트, 16라운드 | 1975 NBS. 3번 적용하면 3DES |
| AES | 대칭 | 128 / 128·192·256 | 2001 NIST, DES를 대체 |
| IDEA | 대칭 | 64 / 128 | 스위스 라이·메시, PES 개선 |
| Skipjack | 대칭 | 64 / 80 | NSA, 클리퍼 칩, 음성 암호화 |
| RSA | 비대칭(공개키) | — | 1978 MIT, **소인수분해**의 어려움 |
| MD5 | 해시 | 512 / 128 | Rivest, MD4 대체 |

- 대칭키 내부 분류: **스트림**(비트 단위: LFSR·RC4·TKIP) / **블록**(DES·SEED·AES·ARIA·IDEA·Skipjack). 대칭키는 빠르지만 관리할 키가 많다.
- 비대칭은 RSA·ECC·ElGamal·DSA만 외우고 나머지는 대칭으로 본다. AES는 대칭이다(2023-2#15에서 비대칭으로 알고 있었다).
- 확인 문항: K#79 · #80 · #81 · #82 · #83

### 2 누가 들어오나 > 접근통제 🟠 · OAuth·AAA ⚪ (p.27, p.66~67)

| 방식 | 기준 | 권한을 정하는 주체 |
| --- | --- | --- |
| DAC (임의) | 사용자의 **신원** | **데이터 소유자**. 만든 사람이 다른 사람에게 권한을 나눠 줄 수 있다 |
| MAC (강제) | 주체·객체의 **보안 등급** 비교 | **시스템** |
| RBAC (역할) | 사용자의 **역할** | **중앙관리자**. DAC·MAC의 단점을 보완했다 |

- **AAA**: 인증(Authentication, 신원 확인) → 인가(Authorization, 권한 부여) → 과금(Accounting, 사용 기록)
- **OAuth**: 비밀번호를 주지 않고 **접근 권한을 위임**하는 표준(공개 API). 핵심요약은 "사용자 인증에 쓰는 표준 인증 방법"이라고 적었다. 단답형에서는 "권한 위임"이라는 트리거로 알아보면 된다.
- 인증 유형 5가지(p.66): 지식(패스워드) · 소유(OTP·스마트카드) · 생체(지문) · 위치(GPS·IP) · 행위(서명)
- 확인 문항: K#29(DAC) · #89(AAA) · #114(SSO) · #120(ISMS)

## db 3. DB — 설계해서 운영하기까지

관계대수와 집계함수가 구조적 약점이다. SQL은 SQL 17문제로 직접 쓰면서 익힌다.

### 4 묻기-이론 > 관계대수 🔴 (p.19~20, p.62)

| 기호 | 이름 | 하는 일 |
| --- | --- | --- |
| σ (시그마) | Select | 조건에 맞는 **행(튜플)** 고르기 = 수평 연산 |
| π (파이) | Project | 지정한 **열(속성)**만 뽑기 = 수직 연산 |
| ⋈ | Join | 공통 속성으로 두 릴레이션 합치기 (= 교차곱 후 Select) |
| ÷ | Division | S의 값을 **모두 가진** R의 튜플에서 S 속성을 뺀 것 |
| ∪ ∩ − | 합·교·차집합 | 합집합은 중복 튜플 제거 |
| × | 교차곱 | 차수 = 두 차수의 **합**, 카디널리티 = 두 카디널리티의 **곱** |

- 관계대수 = **절차적**(어떻게 구할지 순서를 적음) / 관계해석 = **비절차적**(무엇을 원하는지만, ∀·∃). "대절해비"로 외운다.
- 2023-3#19 함정: σ와 π를 뒤바꿔 썼다. **σ = 행(가로로 자름)**, **π = 열(세로로 자름)**.
- 조인 종류(p.62): 세타 조인(=, ≠, <, ≤, >, ≥) ⊃ 동등 조인(= 만) → 중복 속성을 하나 지우면 **자연 조인**. 외부 조인은 안 맞는 튜플에 NULL을 붙여 포함한다.
- 확인 문항: K#16 · #17 · #18 · S#5

### 5 묻기-SQL > 집계함수/NULL 🔴 (p.60~61)

- 그룹 함수: COUNT · SUM · AVG · MAX · MIN · STDDEV · VARIANCE. GROUP BY로 묶고, 그룹 조건은 **HAVING**에 쓴다(WHERE는 개별 행 조건).
- 예제(p.61): 상여금 100 이상인 사원이 2명 이상인 부서

```sql
SELECT 부서, COUNT(*) AS 사원수
FROM 상여금
WHERE 상여금 >= 100
GROUP BY 부서
HAVING COUNT(*) >= 2;
```

- **NULL 규칙**(SQL 17 해설): `COUNT(속성)`은 NULL을 **빼고** 센다. `COUNT(*)`는 NULL이 있어도 행 수 전부를 센다.
- **DISTINCT 위치**: `SELECT DISTINCT COUNT(부서코드)`는 결과 숫자 1개에 DISTINCT가 걸려 의미가 없다. `COUNT(DISTINCT 부서코드)`가 중복을 없앤 뒤 센다.
- 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. AND가 OR보다 먼저 묶인다(S#7).
- 확인 문항: S#1 · #2 · #4 · #7 · #14 · #15

### 5 묻기-SQL > DML 🟠 (p.56~57)

| 명령 | 형식 | 자주 틀리는 곳 |
| --- | --- | --- |
| 삽입 | `INSERT INTO 테이블 [(속성, …)] VALUES (값, …);` | **INTO**를 빼먹음. 모든 속성을 쓸 때만 속성명 생략 가능 |
| 삽입(검색 결과) | `INSERT INTO 테이블(…) SELECT … FROM … WHERE …;` | VALUES 자리에 SELECT가 들어간다 |
| 갱신 | `UPDATE 테이블 SET 속성 = 값[, …] [WHERE 조건];` | 값을 바꿀 때는 SET. 예: `기본급 = 기본급 + 5` |
| 삭제 | `DELETE FROM 테이블 [WHERE 조건];` | WHERE를 빼면 전체 행 삭제. 테이블 구조는 남는다(DROP과 다름) |

- 2023-2#4 메모 "전체 필드면 컬럼명 생략 가능?" → **가능하다**(p.56). 단, 테이블명과 VALUES는 빼면 안 된다.
- DCL: `GRANT 권한 ON 테이블 TO 사용자;` / `REVOKE GRANT OPTION FOR UPDATE ON 고객 FROM STAR;`(권한을 나눠 줄 권한만 취소). ROLLBACK은 COMMIT 안 된 변경을 되돌린다.
- 확인 문항: S#6 · #8 · #9(ALTER) · K#75 · #76

### 5 묻기-SQL > UNION 🟠 · JOIN ⚪ (p.61~62)

| 연산자 | 결과 | 집합 |
| --- | --- | --- |
| UNION | 두 결과를 합치되 **중복 행은 한 번만** | 합집합 |
| UNION ALL | 중복 행도 **그대로** | 합집합 |
| INTERSECT | 공통 행만 | 교집합 |
| EXCEPT | 첫 결과에서 두 번째 결과를 뺀 행 | 차집합 |

- 두 SELECT의 속성 개수와 자료형이 같아야 한다. 2023-3#6은 UNION을 UNION ALL처럼 풀어서 틀렸다.
- **CROSS JOIN**: 두 테이블의 모든 순서쌍. 행 수 = 두 행 수의 곱. 조건 없는 INNER JOIN과 같다.
- **LEFT OUTER JOIN**: INNER JOIN 결과 + 왼쪽에만 있는 튜플(오른쪽 칸은 NULL). RIGHT는 그 반대다.

## sw 4. SW공학 — 만드는 과정

디자인패턴은 기록이 8건으로 가장 많이 흔들린 태그다. 나머지는 **순서 외우기**(결합도·응집도)와 **선 모양**(UML)이다.

### 4 설계-패턴 > 디자인패턴 🟠 (p.39~41)

생성 = 객체를 **만들 때**, 구조 = **짜 맞출 때**, 행위 = 객체끼리 **대화하고 책임을 나눌 때**.

| 분류 | 패턴 | 트리거 |
| --- | --- | --- |
| 생성 | Abstract Factory | 인터페이스로 **연관 객체 그룹**을 생성, 한 번에 교체 |
| 생성 | Builder | 작게 분리된 인스턴스를 **건축하듯** 조합, 생성과 표현 분리 |
| 생성 | Factory Method | 생성을 **서브 클래스**가 담당, 가상 생성자 |
| 생성 | Prototype | 원본을 **복제**해 생성 |
| 생성 | Singleton | 인스턴스가 **하나뿐** |
| 구조 | Adapter | 호환되지 않는 인터페이스를 **변환** |
| 구조 | Bridge | 구현부에서 추상층을 **분리**, 독립 확장 |
| 구조 | Composite | 복합·단일 객체를 구분 없이, **트리 구조**(디렉터리 안의 디렉터리) |
| 구조 | Decorator | 객체를 **덧붙여** 기능을 동적으로 확장 |
| 구조 | Facade | 복잡한 서브 클래스 위에 **통합 창구 인터페이스**(Wrapper) |
| 구조 | Flyweight | 인스턴스를 **공유**해 메모리 절약 |
| 구조 | Proxy | **대리자**. 내부 관계는 정리, 외부에는 세부를 숨김 |
| 행위 | Chain of Responsibility | 못 처리하면 **다음 객체로** 넘김(고리) |
| 행위 | Command | 요청을 **객체로 캡슐화**, 재이용·취소·로그 |
| 행위 | Interpreter | 언어의 **문법 표현** 정의(SQL·통신 프로토콜) |
| 행위 | Iterator | 내부 표현 노출 없이 **순차 접근** |
| 행위 | Mediator | 복잡한 상호작용을 **중재자** 객체로 캡슐화, 결합도 감소 |
| 행위 | Memento | 특정 시점 상태로 **되돌리기**(Ctrl+Z) |
| 행위 | Observer | 상태 변화를 다른 객체들에 전달, **일대다**, 발행/구독 |
| 행위 | State | **상태에 따라** 같은 동작을 다르게 |
| 행위 | Strategy | 알고리즘을 캡슐화해 **교환** |
| 행위 | Template Method | 상위가 **골격**, 하위가 세부 |
| 행위 | Visitor | 처리 기능을 별도 클래스로 분리해 각 클래스를 **방문**하며 수행 |

- 2023-2#11: "데이터 구조에서 처리 기능 분리 · 방문"은 Visitor다. Interpreter는 "문법·언어"가 나와야 한다. 보기가 있으면 보기 안에서만 고른다.
- Facade vs Proxy: Facade는 **여러 서브 클래스를 하나의 창구로** 묶고, Proxy는 **한 객체 앞에서 대신** 서 있다.
- 확인 문항: K#43 · #44 · #45

### 2 설계-모양 > UML 관계 🟠 (p.6~7)

| 관계 | 선 모양 | 하는 말 | 예 |
| --- | --- | --- | --- |
| 연관 Association | 실선(방향은 화살표), 다중도 표기 | 서로 관련되어 있다 | 사람 1 — 1 집 |
| 집합 Aggregation | 빈 마름모 ◇ (부분 → 전체) | 포함하지만 **독립적** | 컴퓨터 ◇— 프린터 |
| 포함 Composition | 채운 마름모 ◆ | 전체가 없어지면 부분도 사라짐 | 건물 ◆— 방 |

- 포함·실체화는 핵심요약 p.6~7에 없어서 벼락치기 §4에서 채웠다. 실선은 구조적 관계, 점선은 약한 관계로 보면 된다.
- 구조적 다이어그램(p.7): 클래스 · 객체 · 컴포넌트(구현 단계) · 배치(물리 요소 위치) · 복합체 구조 · 패키지(모델 요소 그룹화)
- 확인 문항: K#4 · #5 · #6 · #7

### 3 설계-품질 > 결합도 🟠 · 응집도 🟠 (p.36~37)

결합도는 **약할수록**, 응집도는 **강할수록** 좋다.

| 결합도 (약 → 강) | 뜻 |
| --- | --- |
| 자료 | 인터페이스가 자료 요소로만 구성 |
| 스탬프 | 배열·레코드 같은 **자료 구조**를 통째로 전달 |
| 제어 | 다른 모듈의 흐름을 제어하는 **제어 신호** 전달, 권리 전도 현상 |
| 외부 | 한 모듈이 선언한 데이터를 다른 모듈이 참조 |
| 공통 | 모듈 밖에 선언된 **전역 변수** 공유 |
| 내용 | 다른 모듈의 **내부 기능·자료를 직접** 참조·수정 |

| 응집도 (강 → 약) | 뜻 |
| --- | --- |
| 기능적 | 모든 요소가 **단일 문제**에 연관 |
| 순차적 | 앞 활동의 **출력이 다음 활동의 입력** |
| 교환(통신)적 | **같은 입출력**으로 서로 다른 기능 |
| 절차적 | 관련 기능을 **순서대로** 수행(입출력 연결은 없음) |
| 시간적 | **특정 시간**에 처리되는 기능을 모음 |
| 논리적 | **유사한 성격**의 처리 요소를 모음 |
| 우연적 | 서로 관련 없는 요소가 모임 |

- 암기: 결합도 "자스제외공내", 응집도 "기순교절시논우"
- 2024-2#9 순차 vs 절차: **출력이 입력으로 이어지면 순차**, 순서만 있으면 절차다.
- 확인 문항: K#36 · #37 · #38 · #39 · #40(팬인/팬아웃)

### 7 테스트 > 블랙박스 · 통합 · 커버리지 · 테스트케이스 🟠 (p.38, p.47~50)

**블랙박스**(기능 테스트, 요구사항 명세를 보며)

- 동치 분할: 타당한 입력과 타당하지 않은 입력을 **균등하게** 나눠 각 구간의 대표값을 넣는다. p.48 예제는 60 · 75 · 82 · 96을 넣었다.
- 경계값 분석: 오류는 **경계에서** 잘 난다. 같은 예제에서 −1 · 0 · 69 · 70 … 100 · 101을 넣었다.
- 원인-효과 그래프(입력 관계와 출력 상황 분석) · 오류 예측(경험·감각) · 비교 검사(여러 버전에 같은 자료)
- 2023-3#16 함정: "구간별 대표값"이면 동치 분할, "경계 양쪽 값"이면 경계값이다.

**화이트박스 커버리지**(p.47~48)

| 기준 | 무엇을 T/F로 |
| --- | --- |
| 문장(구문) | 모든 구문을 한 번 이상 실행 |
| 결정(분기) | 조건식 **전체** 결과를 T 한 번, F 한 번 |
| 조건 | **개별** 조건식을 각각 T 한 번, F 한 번 |
| 조건/결정 | 결정 + 조건을 모두 만족 |
| MC/DC | 개별 조건이 다른 조건과 상관없이 **독립적으로** 전체 결과에 영향 |
| 다중 조건 | 개별 조건의 **모든 조합** |

**통합 테스트**(p.49~50)

- 비점진적 = 빅뱅(모두 미리 결합) / 점진적 = 하향식 · 상향식 · 혼합식
- **하향식**: 상위 → 하위, 아직 없는 하위 모듈을 **스텁(Stub)**으로 대체한다. 깊이 우선 또는 넓이 우선으로 하나씩 교체한다.
- **상향식**: 하위 모듈을 클러스터로 묶고, 아직 없는 상위를 **드라이버(Driver)**로 대신한다.
- 회귀 테스트: 변경된 모듈 때문에 새 오류가 생기지 않았는지 **반복** 확인한다.
- V-모델: 요구사항↔인수 · 분석↔시스템 · 설계↔통합 · 구현↔단위. 인수 테스트의 알파는 개발자 장소, 베타는 사용자 실업무에서 한다.

**테스트 케이스 · 오라클**(p.38, p.50)

- 테스트 케이스 = 요구사항을 지켰는지 확인하는 테스트 항목 명세서. 구성: **테스트 조건 · 테스트 데이터 · 예상 결과**(K#42).
- 오라클 종류: 참(모든 입력) · 샘플링(몇몇 입력) · 추정(나머지는 추정) · 일관성 검사(변경 전후 비교)
- 확인 문항: K#57 ~ #72

## os 5. OS — 프로세스 하나의 생애

계산 문제(스케줄링·페이지 부재)는 표를 직접 그려야 맞힌다. 핵심요약 예제를 손으로 다시 풀어 보자.

### 2 CPU 배정 > 스케줄링 🔴 (p.103~104)

| 기법 | 선점 | 규칙 | 트리거 |
| --- | --- | --- | --- |
| SJF | 비선점 | 실행 시간이 가장 짧은 것부터 | "평균 대기 시간 최소(최적)", 긴 작업은 기아 |
| HRN | 비선점 | 우선순위 = (대기 + 서비스) / 서비스, **큰 것부터** | SJF의 기아 문제 보완 |
| RR | 선점 | 시간 할당량(Quantum)만큼 돌아가며 | 시분할. 할당량이 크면 FCFS와 같고, 작으면 문맥 교환이 늘어난다 |
| SRT | 선점 | **남은 시간**과 새로 도착한 실행 시간 비교 | SJF의 선점 버전, 오버헤드 증가 |

- 공식: **반환 시간 = 완료 − 도착**, **대기 시간 = 반환 − 실행**(= 완료 − 도착 − 실행)
- HRN 예제(p.104): P1 (20+10)/20 = 1.5, P2 (4+20)/4 = 6, P3 (6+10)/6 ≈ 2.67 → P2 → P3 → P1
- SRT 예제(p.104): A(도착 0, 실행 8) · B(1, 4) · C(2, 9) · D(3, 5). 실행 순서는 A 0–1 → B 1–5 → D 5–10 → A 10–17 → C 17–26이다.

| 프로세스 | 완료 | 반환(완료−도착) | 대기 |
| --- | --- | --- | --- |
| A | 17 | 17 | 9 |
| B | 5 | 4 | 0 |
| C | 26 | 24 | 15 |
| D | 10 | 7 | 2 |
| 평균 | — | **13** | **6.5** |

- 주의: 핵심요약 p.104는 반환 시간을 17·5·26·10(평균 14.5)으로 적었다. 이 값은 **완료 시각**이다. 같은 쪽의 대기 공식(완료 − 도착 − 실행)과 맞추면 반환 평균은 13이다(코드로 재계산했다). 대기 평균 6.5는 책과 같다.
- 확인 문항: K#98(상태 전이) · #99(HRN) · #100

### 3 메모리 > 페이지교체 ⚪ (p.101~102)

| 기법 | 교체 대상 |
| --- | --- |
| FIFO | 가장 **먼저 들어온** 페이지 |
| LRU | **가장 오랫동안 사용하지 않은** 페이지(최근 사용 시점 기준) |
| LFU | **사용 빈도가 가장 적은** 페이지(횟수 기준) |
| OPT | 앞으로 가장 오랫동안 쓰지 않을 페이지 |

- p.101 예제(프레임 3개, 참조 2 3 2 1 5 2 3 5): FIFO 부재 6회, LRU 부재 5회. 표를 직접 그려 같은 숫자가 나오는지 확인한다.
- 스케줄링과의 차이(2024-1#9 메모): 스케줄링은 **CPU를 누구에게** 줄지, 페이지 교체는 **메모리에서 무엇을 내보낼지**를 정한다.
- 함께 나오는 용어: Locality(시간·공간 구역성) · 워킹 셋(자주 참조하는 페이지 집합) · 스래싱(처리보다 페이지 교체에 시간이 더 듦)

### 5 명령 > 리눅스 명령 🟠 (p.105)

## pg 6. 프로그래밍 — 원리별 체크

코드 문제는 요약을 읽어서는 늘지 않는다. 아래 원리 한 줄을 먼저 떠올리고, 시나공 코드 PDF를 변수 표로 추적한다. 핵심요약 10장(p.71~99)은 문법이 막힐 때만 찾아본다.

| 지도 위치 | 원리 한 줄 | 풀 문항 |
| --- | --- | --- |
| 5 객체 규칙 > 상속/오버라이딩 🔴 | 메서드는 **실제 객체** 기준, 필드와 static은 **선언 타입** 기준. `super.m()` 안에서 부르는 메서드도 자식 것이 불린다 | 시나공 07_JAVA #3 · #4 · #7 · #8 · #9 |
| 5 객체 규칙 > static · 생성자 | static 메서드는 인스턴스 필드를 못 쓴다(컴파일 에러). 부모 생성자가 먼저 돈다 | 07_JAVA #2 · #4 |
| 2 메모리 > 포인터 🔴 · 2차원배열 🟠 | 주소 칸과 값 칸을 따로 그린다. `%s`는 그 주소부터 `\0`까지, `%c`는 한 글자. `p+1`은 자료형 크기만큼 이동한다 | 04_포인터 #1~#5 |
| 2 메모리 > 구조체 | `p->x`는 `(*p).x`와 같다 | 05_구조체 #1~#3 |
| 3 비트 > 비트연산 🔴 | 2진수로 펼쳐 쓴다. `^`는 다르면 1, `>>`는 2로 나눔. 연산자 우선순위를 확인한다 | 03_제어문 #5 · #6 |
| 4 자기 호출 > 재귀 | 호출 트리를 그리고 반환값을 아래에서 위로 채운다 | 06_사용자정의함수 #9 |
| 6 자료형 > 리스트 🟠 | 슬라이싱 `[시작:끝:간격]`, 끝은 포함하지 않는다. `[::2]`는 처음부터 하나 건너 하나 | 08_Python #2 · #4(lambda) |

문항 번호는 코드에 extends·super·`->`·`>>` 같은 표식이 있는지로 골랐다. 풀다가 성격이 다른 문제가 섞여 있을 수 있다.
